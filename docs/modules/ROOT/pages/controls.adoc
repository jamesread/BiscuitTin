= Controls

BiscuitTin works with a gamepad, a remote control (most present themselves as a keyboard) or a keyboard.

[cols="2,3"]
|===
| Input | Action

| D-pad, left stick, arrow keys or WASD | Move. Hold to repeat.
| A, Start, kbd:[Enter] or kbd:[Space] | Launch, or select in menus.
| B or kbd:[Backspace] | Back. On the home screen, hide the tiles.
| kbd:[Esc] | Back in menus. On the home screen, ask to exit.
| Hold Guide (Xbox button) | Bring the launcher back while an app is running.
| LB / RB (L1 / R1), kbd:[-] / kbd:[=] | Volume down / up, on every screen. See <<volume>>.
| Click the tray icon | Show the launcher, when a tray is available.
| Tray menu *Exit*, kbd:[Ctrl+Q] or *More > System > Exit* | Quit without asking.
| TV remote over HDMI-CEC | Arrows move, Select, Enter or Play select, Exit, Back or Root menu go back. See <<cec>>.
|===

== Control help

The footer shows the controls for the screen you are on, for your _primary_ input device: whichever you used last, or the gamepad if one is connected at startup.
Gamepad hints use button glyphs matched to the controller: Xbox-style, or PlayStation when the controller's name says so.
Keyboard and remote hints show keycaps.

Hide the hints with *More > Settings > Control help*.
*More > Diagnostics > App diagnostics* shows which device is primary, and *More > Diagnostics > Input devices diagnostics* shows each connected gamepad's buttons and sticks live, and the last few keyboard, remote and CEC presses.
On that screen kbd:[Esc], kbd:[Backspace] and kbd:[Enter] leave, so press other keys to test them.

[[volume]]
== Volume

LB and RB (L1 and R1 on PlayStation pads), or kbd:[-] and kbd:[=] (and the keypad kbd:[-] and kbd:[+]), turn the volume down and up in 5% steps.
The level shows at the top of the screen for a couple of seconds.
The xref:web-control.adoc[web remote] has *Vol −* and *Vol +* buttons, which also work while an app is in front.

By default this runs `wpctl` (PipeWire) on the default output, capped at 100%.
For PulseAudio or ALSA, set `volume.upCommand`, `volume.downCommand` and `volume.getCommand`; see xref:config.adoc[].
The gamepad shoulder buttons only reach BiscuitTin while the launcher is showing.

[[battery]]
== Controller batteries

Wireless controllers whose driver reports a battery (most Xbox, PlayStation and Switch pads on a current kernel) are checked every minute.
Below 20%, or when the driver says *Low* or *Critical*, a message says so once, for example `DualSense Wireless Controller battery low (15%)`.
It shows when the launcher next comes back if an app is in front, and warns again only after the controller has been charged.
*Input devices diagnostics* shows each controller's charge beside its name.

[[keep-awake]]
== Screen blanking

Games read gamepads directly, so the X server doesn't see them as activity, and the screensaver or DPMS (`xset s`, `xset dpms`) could blank the TV in the middle of a game.
BiscuitTin reads the gamepads even while an app is in front, and resets the X idle timer when one is used, at most every 30 seconds.
Set `keepAwake: false` to turn this off. On Wayland it does nothing.

This is separate from *Screen off after*, BiscuitTin's own blanking, which only counts time on the launcher.

[[cec]]
== HDMI-CEC

Many TVs send their own remote's buttons to the connected device over HDMI-CEC.

* *Kernel CEC drivers* (Raspberry Pi, many ARM boards and some Intel graphics) present the TV remote as a keyboard. That already works, with nothing to set.
* *libCEC adapters*, such as the Pulse-Eight USB-CEC adapter, need `cec-client` (from libCEC). Install it on the host and set:
+
[source,yaml]
----
cec:
  enabled: true
----

BiscuitTin then runs `cec-client` and reads the key presses from its log; set `cec.command` to change how it runs.
If `cec-client` exits (for example, the adapter is unplugged), it is started again every 30 seconds.
*App diagnostics* shows *HDMI-CEC* as running or not, and *Input devices diagnostics* lists CEC presses as, for example, `CEC up`.
CEC presses wake the screen and the idle tiles, like any other input.

== Idle and hiding the tiles

While a background image is showing, or RSS feeds have articles, the tiles, menus and hints fade out after `idleFadeSeconds` (default 20) without input, so the photo can be enjoyed.
The title, clock and photo credit stay.
Configured xref:rss.adoc[RSS headlines] fade in on the home screen in their place.
Pressing B or Backspace on the home screen hides the tiles straight away.
kbd:[Esc] on the home screen asks whether to exit.

Any key, button or stick movement brings them back within a fifth of a second.
That first input only wakes the screen; it doesn't also move or launch anything.
The mouse pointer is shown while the tiles are up, and hidden when idle.

Moving, confirming and going back play a short, quiet tick. The first input
that only wakes the idle screen is silent.
